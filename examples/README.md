# 示例

目录里有两个成品，一个看「能不能跑」，一个看「真实效果长什么样」。

## 最小示例：`sample.pdf`

`sample.md` 是一份最小可跑的书稿，用来验证 `md-to-book-pdf` 的章节拆分逻辑。

同目录下的 `sample.pdf` 是**跑通后的成品参考**（forest 深墨绿封面，5 页，2 章 + 可点击目录 + 侧边栏书签），先看它就能知道最终效果长什么样——注意封面是**满版铺满整页**的，四边没有白边。

它刻意用了**中文书稿最常见的写法**：

- 顶部 `# 书名` + 一段 frontmatter 引用；
- 一个 `## 目录` 及其列表（应被自动跳过，不当成章节）；
- 正文用 `## 第 N 章` 分级。

## 真实书稿成品：`闭环.pdf`

`sample.pdf` 只有 5 页、无配图，用来确认流程通不通；
`闭环.pdf` 是**同一条流水线跑出来的真实书稿成品**（作者：古思），用来看工具真实能到什么水平：

| | `sample.pdf`（最小示例） | `闭环.pdf`（真实书稿） |
|---|---|---|
| 规模 | 5 页 / 2 章 / 无图 | 55 页 / 7 章 / 20 张配图 |
| 封面 | forest 深墨绿 | red-bright 鲜亮红 + 副标题 + 描述段落 + 7 个步骤圆圈 |
| 目录 | 可点击 | 可点击，页码自动回填（3/8/14/21/28/34/40） |
| 书签 | 侧边栏书签 | 侧边栏 7 章书签 |
| 章节扉页 | 有 | 有（系列名「第一个100块」+ 章号 + 标题） |
| 满版封面 | 四边 0mm | 四边 0mm（机器校验通过） |
| 体积 | 491 KB | 9.2 MB |

生成命令（`--split-by h2` 因为书稿用 `## 第 N 章` 分章）：

```bash
python scripts/make_book.py \
  --md-file 书稿.md \
  --split-by h2 \
  --title "闭环" --author "古思" \
  --subtitle "在你睡觉时赚钱" --series "第一个100块" \
  --desc "用企业家思维重新理解写作……" --steps 7 \
  --cover-style red-bright \
  --out 闭环.pdf
```

⚠️ **带图书稿的两个坑**（真实书稿才会遇到，`sample.md` 测不出来）：

1. **正文图片是相对路径**，HTML 生成在 `build/` 下，所以书稿的 `images/` 需要出现在 `build/images/`，否则图会丢。见 SKILL.md 踩坑第 8 条。
2. **`--split-by h2` 曾会吞掉正文图片**（`startswith("!")` 误删），已修复。若你的成品 PDF 里图片数为 0，见 SKILL.md 踩坑第 20 条。

## 跑一下最小示例

```bash
cd ..
python scripts/make_book.py \
  --md-file examples/sample.md \
  --split-by h2 \
  --title "像企业家一样写作" \
  --author "示例作者" \
  --cover-style forest \
  --out examples/sample.pdf
```

预期结果：

- 封面 1 页（forest 深墨绿主题，**满版铺满整页、四边 0mm**）
- 目录页（来自 `## 目录`，不计入正文章节）
- 第一章、第二章各占一页（章节扉页 + 正文）
- 页脚 `{书籍标题} · {页码}`，目录页底部有跳转提示

末尾还会自动打印满版校验结果：

```
左边留白 0.00 mm  [OK]   …
[通过] 封面满版铺满整页（四边留白 ≤ 0.5 mm），无白边。
```

如果 `## 目录` 被当成了「第一章」，说明 `--split-by` 没传 `h2`；加上即可。
若校验报出几毫米的留白，说明封面 CSS 被改坏了，见 SKILL.md 踩坑第 7 条。
